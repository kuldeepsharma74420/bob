Modes

Q: How many modes do you have?

Bob has 3 built-in modes, each optimized for a specific type of task:

ModeBest ForTool Access
PlanPlanning, designing, strategizing before implementationRead + limited write (.md/.txt)
AgentWriting, modifying, refactoring codeFull — read, write, execute
AskExplanations, documentation, answering questionsRead only
2

Permissions (Groups) Feature

Q: What is the permissions feature and how to use it?

When creating a custom mode, you control what it can do using permission groups in the groups field of the YAML config.

GroupWhat It Allows
readReading files and looking up code symbols
editWriting and modifying files
executeRunning shell commands
mcpUsing MCP server tools
skillUsing the use_skill tool
todoUsing the update_todo_list tool
subagentUsing the spawn_subagent tool
modeUsing the switch_mode tool

Key Rules

  • Omitting groups gives the mode NO tool access
  • Use exact group names — typos silently grant nothing
  • No duplicate group names — duplicates drop the entire file
  • Restrict editing to specific file types using fileRegex
3

Purpose of Custom Modes

Q: Why do we need to create custom modes?
  1. Focused Behavior / Persona — Each mode has its own roleDefinition (e.g. Security Reviewer, Docs Writer, DevOps Engineer)
  2. Controlled Tool Access — Restrict what Bob can do (read-only, docs-only, no-shell)
  3. Context Switching — Different tasks need different mindsets
  4. Team / Project Standardization — Workspace-scoped modes can be committed to version control
  5. Custom Instructions Per Mode — Each mode can enforce project-specific conventions

DevOps Engineer Custom Mode

Q: Can we create a custom mode for deploying applications in Kubernetes?

Yes! A DevOps Engineer mode was created globally.

customModes:
  - slug: devops-engineer
    name: DevOps Engineer
    roleDefinition: >-
      You are an experienced DevOps engineer specializing in
      Kubernetes, Docker, Helm, and CI/CD pipelines.
    groups:
      - read
      - edit
      - execute
      - mcp
Created: ~/.bob/settings/custom_modes.yaml — Global scope, available in all workspaces

How to Create a Custom Mode Manually

Q: Can I create the mode manually? Give the steps.
  1. Decide the Scope — Global (~/.bob/settings/custom_modes.yaml) or Workspace (.bob/custom_modes.yaml)
  2. Open or Create the File — Navigate to the file path
  3. Write Your Mode Entry — Use the YAML template with slug, name, roleDefinition, groups
  4. Choose Permission Groups — Only include what the mode actually needs
  5. Optionally Restrict File Editing — Use fileRegex
  6. Ensure Slug is Unique — Letters, numbers, dashes only
  7. Append to Existing File — Never overwrite
  8. Save the File — Hot-reloads automatically

Common Mistakes

MistakeResult
Duplicate slugEntire file is dropped
Wrong group name (write, command)Silently grants nothing
Invalid fileRegexEntire file is dropped
Global mode in wrong pathMode never loads
Smart/curly quotesYAML parsing fails

MCP Tools — Model Context Protocol

Q: What is the MCP tool and what is its purpose?

MCP = Model Context Protocol — an open protocol that allows Bob to connect to external tools and services through a standardized interface.

Without MCPWith MCP

CloudWatchCLI commands onlyLive logs, metrics, alarms

AWS RDS MCP Server

Q: Configure AWS RDS MCP server (workspace-scoped, IAM Role auth)
{
  "mcpServers": {
    "aws-rds": {
      "command": "npx",
      "args": ["-y", "@aws/amazon-rds-mcp-server"],
      "env": { "AWS_REGION": "us-east-1" }
    }
  }
}
Configured: .bob/mcp.json — Workspace scope, IAM Role auth (no keys needed)

Prerequisites

  • Node.js installed — run node --version to check
  • Update AWS_REGION to match your actual region
  • IAM Role needs: rds:DescribeDBInstances, rds-data:ExecuteStatement

k8s-deploy Skill

Q: Create a skill for deploying applications to Kubernetes
Created: ~/.bob/skills/k8s-deploy/SKILL.md — Global scope, manual activation via /k8s-deploy

Workflow Steps

  1. Gather app details (name, image, port, replicas, namespace)
  2. Choose deployment method — plain manifests or Helm chart
  3. Generate Kubernetes manifests OR full Helm chart
  4. Validate using kubectl dry-run or helm lint
  5. Apply the deployment to the cluster
  6. Verify pods are running, check logs if failures
  7. Provide summary and next steps

Todo List — update_todo_list

Q: What is the todo tool?

Bob's built-in task management system for tracking progress of complex, multi-step work.

SymbolMeaning

[-]In Progress
[ ]Pending

Rules

  • Never removes unfinished tasks
  • Adds new todos dynamically when discovered

Subagents — spawn_subagent

Q: What is the spawn_subagent tool?

Creates an independent agent in its own isolated context to handle focused, self-contained work — then automatically returns a summary and is destroyed.

Lifecycle

Bob CREATES subagent
  --> ASSIGNS focused task
  --> Subagent WORKS independently
  --> RETURNS summary to Bob
  --> AUTOMATICALLY DESTROYED
TypeNameBest For
Explorer"explore"Reading files, researching codebase
General"general"Full implementation work

fork_context Option

  • false — Subagent only needs the description (default)
  • true — Subagent needs prior conversation history

Mode Switching — switch_mode

Q: What is the switch_mode tool?

Allows Bob to automatically switch between modes during a task without manual intervention from the user.

Example from This Session

Bob was in Plan mode, tried to write custom_modes.yaml, got blocked (Plan only allows .md/.txt), then automatically switched to Agent mode to complete the task.

ScenarioSwitches To
Need to write or modify codeAgent mode
Need to plan before codingPlan mode
Need to explain or answerAsk mode
Implement a planned subtaskAgent mode

Bob Findings

Q: What is the Bob Findings feature in the status bar?

A dedicated UI panel in the status bar that collects and displays important observations, issues, suggestions, or insights Bob notices while working — separate from the chat conversation.

TypeExample
BugsNull pointer risk in auth.js line 42
WarningsFunction has no error handling
Security IssuesAPI key hardcoded in config.js
SuggestionsLoop can be optimized using map()
Code SmellsFunction is 200 lines — consider splitting

The counter badge (showing 0 in the status bar) increases as Bob flags issues. Click to open the panel.
